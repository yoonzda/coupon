# 옹진 관광 쿠폰 플랫폼 - 개발 프로세스 및 시스템 공통 규칙 (System Rules)

이 문서는 옹진 관광 쿠폰 플랫폼의 모든 페이지(사용자, 발행처, 가맹점, 관리자)와 백엔드 API 개발 시 **절대적으로 준수해야 하는 공통 프로세스 규칙**입니다.

---

## 1. 쿠폰 3단계 라이프사이클 (3-Stage Life Cycle Pipeline)
모든 쿠폰 관련 기능 및 화면 표시는 아래 3단계 구분을 완벽하게 준수해야 합니다.

1. **`[1단계: 쿠폰 발급]`**
   - **발생 시점**: 발행처(여객터미널, 키오스크 등)에서 결제 발생 시 쿠폰이 즉시 생김.
   - **소유자 정보**: 지갑 등록 전이므로 소유자 정보는 **`- (미등록 대기)`** 로 표출 및 결제시각 기록.
   - **우선권**: 발행처에서 돈을 지불하고 발급된 몫이므로 100% 확정 쿠폰.

2. **`[2단계: 쿠폰 등록]`**
   - **발생 시점**: 관광객이 모바일 랜딩 페이지에서 휴대폰 본인 인증(OTP) 완료 후 모바일 지갑으로 수령.
   - **소유자 정보**: 소유자 정보가 관광객의 휴대폰 번호 **`010-XXXX-XXXX`** 로 자동 갱신.
   - **중요 규칙**: 동일한 관광객(전화번호)이 이미 미사용 쿠폰을 보유하고 있더라도, 현장 QR 스캔 시 **무제한 추가 등록 수령 허용**.

3. **`[3단계: 쿠폰 사용]`**
   - **발생 시점**: 가맹점에서 QR/barcode 결제하여 할인 적용 완료 (`status = 'used'`).
   - **지출 처리**: 지자체 실제 정산 대상 지출로 확정 처리.

---

## 2. 보안 및 어뷰징 방지 규칙 (Security Rules)
- **보안 토큰 전용**: 주소 접근 시 단순 정수 `allocationId=1` 식별자 파라미터 접속 전면 금지. AES-256 보안 난수 토큰(`token=d9bafe41...`)만 허용.
- **1회성 세션 검증**: 카카오톡 주소 공유나 원격 접속 수령 어뷰징을 막기 위해 키오스크 1회성 세션(`kioskSessionId`) 기반으로 이미 수령된 링크는 재접속 차단.

---

## 3. 예산 5대 회계 지표 공식 (Budget Accounting Standards)
모든 예산 관련 계산 및 표시는 아래 회계 공식을 엄격히 따릅니다.

- **`[1. 총 사업 예산]`**: 지자체 전체 설정 예산 (기본 2,000,000원)
- **`[2. 발행처 배정 예산]`**: 관리자가 발행처(터미널 등)에 배정 완료한 총 금액 (`SUM(face_value * total_count)`)
- **`[3. 실제 집행 예산]`**: 가맹점에서 3단계 할인 사용 완료된 순수 지출액
- **`[4. 점유/예약 예산]`**: 1단계(발급) 및 2단계(등록) 상태로 관광객이 보유하고 있는 사용 대기 묶임 금액
- **`[5. 추가 배정 가능 잔액]`**: `[총 사업 예산] - [발행처 배정 예산]` (이중 차감 없이 깔끔한 추가 배정 한도)
- **만료 처리**: 유효기간(1년) 만료 시 `점유 예산`에서 자동 해제되며 발행처의 발급 한도로 100% 환원.

---

## 4. 디스플레이 및 UX 규칙 (Display Standards)
- **관광객 랜딩 화면 (`landing.html`)**:
  - `대상 구분` 항목 완전 삭제.
  - `유효 기간`은 `발급일로부터 1년간 유효`로 지정.
- **관리자 화면**:
  - 미등록 1단계 상태 쿠폰 소유자는 **`- (미등록 대기)`** 표출.
  - 불필요하고 딱딱한 전문 용어 대신 누구나 직관적으로 이해할 수 있는 쉬운 한글 표현 사용.
  - 어색하거나 튀는 이모지 아이콘 사용 금지.
