# 옹진 관광 쿠폰 플랫폼 - 개발 프로세스 및 시스템 공통 규칙 (System Rules)

이 문서는 옹진 관광 쿠폰 플랫폼의 모든 페이지(사용자, 발행처, 가맹점, 관리자)와 백엔드 API 개발 시 **절대적으로 준수해야 하는 공통 프로세스 규칙**입니다.

---

## 1. 쿠폰 3단계 라이프사이클 (3-Stage Life Cycle Pipeline)
모든 쿠폰 관련 기능 및 화면 표시는 아래 3단계 구분을 완벽하게 준수해야 합니다.

1. **`[1단계: 쿠폰 발급]`**
   - **발생 시점**: 발행처(여객터미널, 키오스크 등)에서 결제 발생 시 쿠폰이 즉시 생김.
   - **소유자 정보**: 지갑 등록 전이므로 소유자 정보는 **`- (미등록 대기)`** 로 표출 및 결제시각 기록.
   - **우선권**: 발행처에서 돈을 지불하고 발급된 몫이므로 100% 확정 쿠폰.

2. **`[2단계: 쿠폰 등록]`**
   - **발생 시점**: 관광객이 모바일 랜딩 페이지에서 휴대폰 본인 인증(OTP) 완료 후 모바일 지갑으로 수령.
   - **소유자 정보**: 소유자 정보가 관광객의 휴대폰 번호 **`010-XXXX-XXXX`** 로 자동 갱신.
   - **중요 규칙**: 동일한 관광객(전화번호)이 이미 미사용 쿠폰을 보유하고 있더라도, 현장 QR 스캔 시 **무제한 추가 등록 수령 허용**.

3. **`[3단계: 쿠폰 사용]`**
   - **발생 시점**: 가맹점에서 QR/barcode 결제하여 할인 적용 완료 (`status = 'used'`).
   - **지출 처리**: 지자체 실제 정산 대상 지출로 확정 처리.

---

## 2. 보안 및 어뷰징 방지 규칙 (Security Rules)
- **보안 토큰 전용**: 주소 접근 시 단순 정수 `allocationId=1` 식별자 파라미터 접속 전면 금지. AES-256 보안 난수 토큰(`token=d9bafe41...`)만 허용.
- **1회성 세션 검증**: 카카오톡 주소 공유나 원격 접속 수령 어뷰징을 막기 위해 키오스크 1회성 세션(`kioskSessionId`) 기반으로 이미 수령된 링크는 재접속 차단.

---

## 3. 예산 4대 회계 지표 공식 및 무배정 발급 정책 (Budget Accounting Standards)
발행처 사전 쿠폰 배정(수량 할당) 과정 없이, 각 발행처에 등록된 상품 금액 기준으로 즉시 쿠폰이 발급되며 모든 예산 관련 계산 및 표시는 아래 회계 공식을 엄격히 따릅니다.

- **`[1. 총 사업 예산]`**: 지자체 전체 설정 예산 (기본 2,000,000원)
- **`[2. 실제 집행 예산]`**: 가맹점에서 3단계 할인 사용 완료된 순수 지출액 (`status = 'used'`)
- **`[3. 점유/예약 예산]`**: 1단계(미등록) 및 2단계(등록 완료) 상태로 현재 보유 중인 사용 대기 묶임 금액 (`status != 'used' AND status != 'expired'`)
- **`[4. 잔여 예산]`**: `[총 사업 예산] - ([실제 집행 예산] + [점유/예약 예산])` (현재 추가로 발행·집행 가능한 가용 예산)
- **만료 처리**: 유효기간(1년) 만료 시 `점유/예약 예산`에서 자동 해제되며 `잔여 예산`으로 100% 환원.

## 4. 디스플레이 및 UX 규칙 (Display Standards)
- **관광객 랜딩 화면 (`landing.html`)**:
  - `대상 구분` 항목 완전 삭제.
  - `유효 기간`은 `발급일로부터 1년간 유효`로 지정.
- **관리자 화면**:
  - 미등록 상태 쿠폰 소유자는 **`-`**, 등록된 쿠폰 소유자는 휴대폰 번호 뒷 4자리 표출.
  - 쿠폰 상태는 1·2·3단계 문구 없이 **`미등록` / `등록 완료` / `사용 완료`** 로 간결하게 표출.
  - 불필요하고 딱딱한 전문 용어 대신 누구나 직관적으로 이해할 수 있는 쉬운 한글 표현 사용.
  - 어색하거나 튀는 이모지 아이콘 사용 금지.

---

## 5. 화면 디자인 및 미니멀리즘 UI/UX 절대 규칙 (Minimalist UI Safeguards)
사용자의 디자인 선호도를 위반하여 복잡한 대시보드나 설명문이 가득한 화면을 만드는 일을 방지하기 위한 **절대 준수 수칙**입니다.

- **핵심 레퍼런스 (`frontend/merchant/index.html` 스타일)**:
  - 화면 전체 정중앙 정렬(`min-height: 100dvh; display: flex; align-items: center; justify-content: center; background: #f8fafc;`)과 여백이 살아있는 심플한 카드 그리드(`.intro-wrapper`, `.card-grid`, `.main-card`) 구성을 기본 원칙으로 삼습니다.
  - 얇고 정교한 선형 아이콘(`stroke-width: 1.25`)과 간결한 단어형 레이블(`관광객`, `발행처`, `가맹점`, `관리자` 등)만 배치합니다.
- **요청하지 않은 텍스트·장식 요소 전면 금지**:
  - 상단 네비게이션 바(Top Bar), 하단 푸터(Footer), 영문 서브타이틀(Eyebrow), 뱃지/태그, 장황한 부연 설명문, URL 텍스트 박스를 절대 임의로 넣지 않습니다.
- **과잉 기능 및 임의 하드코딩 금지**:
  - 테스트용 QR 등은 금액별 선택 버튼이나 복잡한 옵션 없이 **단 하나의 깔끔한 QR**로만 구성합니다.
  - 이미 구축된 테스트 인증 프로세스(휴대폰 번호 입력 후 생성된 난수 인증번호를 터치해 입력하는 방식)를 임의로 고정 번호(`123456` 등)로 지정하거나 화면에 불필요한 안내 문구로 적지 않습니다.
